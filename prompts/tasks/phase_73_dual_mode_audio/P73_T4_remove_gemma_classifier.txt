You are tasked with removing the Gemma/llamafile local LLM classifier from BarnOwl AI (P73-T4).

════════════════════════════════════════════════════════════════
TASK CONTEXT
════════════════════════════════════════════════════════════════

The app currently uses a local llamafile binary running Gemma-3-270m-it-Q8_0 as a
"turn-detection" classifier. After every STT transcript chunk passes the ONNX noise
filter, the app sends it to Gemma via HTTP and asks: "Is this a complete question?"
before triggering the main Cloudflare LLM call.

This causes two critical issues in production:
1. Gemma takes 2–10 seconds on CPU to return a single true/false value.
2. The classifier and the main LLM compete for the same 2 CPU threads, causing
   the classifier HTTP request to time out while the main LLM is mid-stream.
   Result: `context deadline exceeded` → buffer cleared → question DROPPED.

Root cause analysis: Gemma adds ZERO value because:
- The ONNX embedding classifier in `wails-app/backend/filter/classifier.go` already
  separates noise from real interview questions using cosine similarity.
- Session history (`sessionMgr.GetRecentTurns()`) in `pipeline.go` already handles
  multi-turn follow-up context ("Explain more" becomes meaningful because of history).
- The main answer LLM is Cloudflare AI (remote), NOT the local llamafile.
  llamafile is ONLY used for Gemma classification — nothing else.

Decision: Replace Gemma with an instant always-true classifier. Any transcript that
survives the ONNX noise filter is treated as a complete, actionable question.
