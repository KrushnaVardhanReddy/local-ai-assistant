TASK: P40-T8 — Stripe Payment Integration (Supabase Edition)

═══════════════════════════════════════════════════════════════
BACKGROUND & CONTEXT
═══════════════════════════════════════════════════════════════

The Cloud Edition uses a usage-based billing model. Users pay a $2 service fee per interview session + the API pass-through cost. They will purchase "credits" (sessions) via Stripe Checkout.

We are using Supabase Postgres as our database. The `profiles` table has a `payg_sessions` column.

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════

1. CREATE STRIPE CHECKOUT SESSION:
   - Provide an endpoint (`POST /create-checkout-session`) that the Tauri frontend can call.
   - It should generate a Stripe Checkout URL to sell a "5-Pack of Interviews" for $10.00.
   - It must accept the user's `userId` (UUID) from the frontend and pass it into the Stripe Checkout session's `metadata` or `client_reference_id` so we know who paid when the webhook fires.

2. STRIPE WEBHOOK HANDLER:
   - Provide an endpoint (`POST /api/webhook/stripe`) to receive Stripe events.
   - When a `checkout.session.completed` event is received, extract the `userId`.
   - Update the Supabase `profiles` table: increment `payg_sessions` by `+5`.

3. FRONTEND INTEGRATION:
   - Add a "Buy 5 Interviews for $10" button in `Settings.svelte`.
   - On click, hit `/create-checkout-session` and redirect the user's browser to the returned Stripe URL.
