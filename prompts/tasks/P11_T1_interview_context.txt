TASK: P11-T1 — Resume Upload & LLM Context Extraction

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Allow the user to upload their resume (PDF or TXT) inside the Settings panel.
The backend will extract raw text from the resume, pass it to the LLM with a
specific extraction prompt, and store the resulting concise candidate summary
in memory. This summary is then automatically appended to every system prompt,
personalizing all LLM answers without the user manually typing anything.

═══════════════════════════════════════════════════════════════
BACKGROUND & MOTIVATION
═══════════════════════════════════════════════════════════════
Currently the AI answers every question generically, like a textbook.
Parakeet AI and similar tools ask for the user's resume upfront so the AI
knows: "This candidate has 3 years of React experience and is applying for
a Senior role at Stripe" — and can tailor its hints accordingly.

Asking the user to manually summarize their resume is friction. Instead, let
the LLM read the resume and extract what it needs in a single one-time pass.
The extraction result is a compact ~150-word candidate profile stored in memory
and prepended to every subsequent system prompt automatically.

═══════════════════════════════════════════════════════════════
BACKEND CHANGES: app.py
═══════════════════════════════════════════════════════════════

1. Add a new global variable at the top of app.py:
   ```python
   candidate_context: str = ""  # Extracted from uploaded resume
   ```

2. Add a new Pydantic model:
   ```python
   class ResumeModel(BaseModel):
       text: str  # Raw text content of the uploaded resume
   ```

3. Add a new POST endpoint `/api/resume/extract`:
   - Accept `ResumeModel` (the raw text of the resume, extracted by the frontend)
   - Call the LLM (using the existing `llm_client`) with this extraction prompt:
     ```
     system: "You are a resume parser. Extract the candidate's key technical skills,
              years of experience, notable projects, and target role from the resume text.
              Be concise. Output a single paragraph of max 150 words. No bullet points."
     user: <the resume text>
     ```
   - Use a NON-STREAMING call (collect the full response, do not stream)
   - Store the result in the global `candidate_context` variable
   - Return `{"status": "success", "summary": candidate_context}`

4. Add a GET endpoint `/api/resume/context`:
   - Returns `{"context": candidate_context}`

5. Modify the existing LLM system prompt assembly (around line 360 in app.py)
   to append `candidate_context` if it is non-empty:
   ```python
   system_content = config.SYSTEM_PROMPT
   if candidate_context:
       system_content += f"\n\nCandidate profile: {candidate_context}"
   if combined_context:
       system_content += f"\n\n{combined_context}"
   ```
   This ensures the candidate profile is always silently added to every query.

Add a new "Resume Context" section below the existing Persona dropdown and

Section contents:

   (styled as section-label: font-size 0.7rem, uppercase, letter-spacing 0.1em, color #666)

5. In `onMount`, call GET `{apiUrl}/api/resume/context`. If context is non-empty,
   show status as "✅ Profile active (from previous session)" using a note that
   context is stored server-side in memory and will reset on backend restart.

IMPORTANT IMPLEMENTATION NOTES
═══════════════════════════════════════════════════════════════
- The LLM call for extraction must be a simple non-streaming HTTP POST to the
  LLM provider using the existing `llm_client.stream()` pattern BUT collect
  all tokens into a single string before returning. Use `async for token in client.stream(messages): result += token`
- The `candidate_context` is IN MEMORY ONLY. It resets when the backend restarts.
  This is intentional — privacy-first design, nothing persisted to disk.
- For PDF parsing on the frontend, use `pdfjs-dist`. Install it:
  `cd frontend && npm install pdfjs-dist`
  Import with: `import * as pdfjsLib from 'pdfjs-dist';`
  Set the worker: `pdfjsLib.GlobalWorkerOptions.workerSrc = new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url).href;`
- Keep all styling consistent with the existing dark theme in Settings.svelte:
  background #222, border 1px solid #444, text white, labels #aaa.
