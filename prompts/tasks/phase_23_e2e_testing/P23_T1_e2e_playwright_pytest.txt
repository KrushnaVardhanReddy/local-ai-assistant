OBJECTIVE
═══════════════════════════════════════════════════════════════
Build out a bulletproof End-to-End testing suite to ensure high reliability for the core AudioService pipeline. The suite must cover both frontend UI interactions via Playwright (mocking Tauri IPC if necessary) and backend WebSocket/HTTP endpoints via Pytest.

REQUIREMENTS
═══════════════════════════════════════════════════════════════
1. Backend Integration Tests (Pytest - tests/e2e/test_backend_e2e.py)
   Test EVERY HTTP endpoint and WebSocket interaction using `httpx` and an async WS client. Mock external LLM/STT APIs.
   - `GET /health`: Verify 200 OK and correct JSON structure.
   - `POST /session/end`: Verify it exports session history and generates a Scorecard JSON.
   - `POST /session/clear`: Verify the in-memory `interview_session` singleton resets correctly.
   - `POST /rag/upload`: Test file upload (PDF/TXT) and verify successful ChromaDB ingestion response.
   - `GET /rag/search`: Verify semantic search returns top-K context chunks.
   - `POST /vision/analyze`: Post a base64 image and verify the extracted LeetCode problem text is returned.
   - `WebSocket /ws (Audio Ingestion)`: Send mock audio bytes, verify VAD intent filtering.
   - `WebSocket /ws (LLM Output)`: Verify the backend emits `{"type": "transcript", ...}` and `{"type": "llm_chunk", ...}` JSON frames back to the client.

2. Frontend UI Tests (Playwright - frontend/e2e/assistant.spec.ts)
   Use Playwright to spin up the Svelte frontend and test EVERY interactive feature and button.
   - **Settings Panel:** 
     - Click the Settings gear icon, verify the panel slides out.
     - Toggle the 'LLM_PROVIDER' and verify it saves.
     - Change the 'Language Preference' dropdown.
   - **Microphone UI:**
     - Verify the mic status dot changes color based on state (Listening/Processing).
   - **Transcript Chip Bar:**
     - Mock a WS "transcript" event, verify the Chip appears in the UI.
     - Click the Chip, verify the priority question is sent over the WS.
     - Verify Chips auto-clear or can be manually dismissed.
   - **The Brain Panel (Markdown rendering):**
     - Inject a mock LLM response containing a python code block.
     - Verify `shiki` syntax highlighting is applied to the DOM elements.
   - **Stealth Hotkeys (Mocked Tauri IPC):**
     - Simulate `Ctrl+Shift+S` and verify it triggers the Vision Copilot screenshot logic.
     - Simulate `Ctrl+Shift+1` and verify it triggers the first Transcript Chip.

3. Tauri Backend Tests (Rust `cargo test` - frontend/src-tauri/src/)
   Write exhaustive unit and integration tests for the Rust Tauri backend.
   - Test IPC commands (e.g., screenshot capture to base64).
   - Test that global stealth hotkeys correctly register and deregister.
   - Verify window transparency and "always on top" behaviors via Tauri mock API.

4. Makefile Updates
   - Add `make test-e2e` to trigger backend (pytest), frontend (playwright), and Tauri (cargo test) headlessly.
