TASK: P23-T1 — Comprehensive E2E Testing Suite (Playwright + Pytest)

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Build out a bulletproof End-to-End testing suite to ensure high reliability for the core AudioService pipeline. The suite must cover both frontend UI interactions via Playwright (mocking Tauri IPC if necessary) and backend WebSocket/HTTP endpoints via Pytest. 

This ensures that the primary flows (Audio input → STT/Gemini → LLM reasoning → UI rendering) and the recently added Phase 15-22 features never regress.

═══════════════════════════════════════════════════════════════
REQUIREMENTS
═══════════════════════════════════════════════════════════════

1. Database / External API Mocking
   Since running a full local Postgres/Supabase instance in CI is heavy and error-prone, you MUST mock all `httpx` HTTP calls to Supabase, Stripe, and external LLM/STT APIs in the Pytest suite (e.g., using `pytest-httpx` or `respx`). 

2. Backend Integration Tests (Pytest - tests/e2e/test_backend_e2e.py)
   Test EVERY HTTP endpoint and WebSocket interaction using `httpx` and an async WS client. Mock external dependencies.
   - `GET /health`: Verify 200 OK and correct JSON structure.
   - `POST /session/end`: Verify it exports session history and generates a Scorecard JSON.
   - `POST /session/clear`: Verify the in-memory `interview_session` singleton resets correctly.
   - `POST /rag/upload`: Test file upload and verify successful ChromaDB ingestion response.
   - `GET /rag/search`: Verify semantic search returns top-K context chunks.
   - `POST /vision/analyze`: Post a base64 image and verify extraction.
   - `POST /api/stripe_webhook`: Test Stripe signature validation, idempotency (check if already converted), and reward logic.
   - `POST /api/job_description`: Test PDF upload for context grounding.
   - `WebSocket /ws (Auth & Locks)`: Test `check_and_register_device` and `acquire_session_lock` flows, including `device_limit_reached` and `already_active` rejection paths.
   - `WebSocket /ws (Mock Mode)`: Send `mock_mode_toggle` and test that `mock_audio` frames are returned instead of standard coaching.
   - `WebSocket /ws (Normal Flow)`: Send mock audio bytes, verify `transcript` and `llm_chunk` JSON frames.

3. Frontend UI Tests (Playwright - frontend/e2e/assistant.spec.ts)
   Use Playwright to spin up the Svelte frontend and test EVERY interactive feature and button.
   - **Settings Panel:** 
     - Click the Settings gear icon, verify the panel slides out.
     - Toggle the 'LLM_PROVIDER' and verify it saves.
     - Change the 'Code Language Preference' dropdown.
     - Change the 'Interview Language (STT & LLM Override)' dropdown.
   - **Plan Gating & Features:**
     - Mock a WS `plan` event (e.g., demo/payg). Verify the Vision copilot button is disabled.
   - **Mock Interview UI:**
     - Click the Mock Mode mic icon (`record_voice_over`). Verify the green overlay appears and hands-free indicator displays.
   - **Click-through Mode:**
     - Test the toolbar toggle (mouse/back_hand icon).
   - **Device Dashboard:**
     - Test the `/dashboard/devices` route UI. Verify list rendering and remove button presence.
   - **Transcript Chip Bar:**
     - Mock a WS "transcript" event, verify the Chip appears in the UI.
     - Click the Chip, verify the priority question is sent over the WS.
   - **The Brain Panel (Markdown rendering):**
     - Inject a mock LLM response containing a python code block.
     - Verify syntax highlighting is applied.
   - **Stealth Hotkeys (Mocked Tauri IPC):**
     - Simulate `Ctrl+Shift+S` and verify it triggers the Vision Copilot screenshot logic.
     - Simulate `Ctrl+Shift+M` and verify click-through mode toggles.

4. Tauri Backend Tests (Rust `cargo test` - frontend/src-tauri/src/)
   Write exhaustive unit and integration tests for the Rust Tauri backend.
   - Test IPC commands (e.g., screenshot capture, get_machine_id, load_token).
   - Test that global stealth hotkeys correctly register and deregister.

5. Makefile Updates
   - Add `make test-e2e` to trigger backend (pytest), frontend (playwright), and Tauri (cargo test) headlessly.
