═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Build a fully automated, local-first "smart context pipeline" that runs before every
cloud LLM call. It has two stages:

STAGE 1 — SmolLM2 Multi-Class Question Classifier:
  Automatically classify the interviewer's question into one of several categories,
  then dynamically adjust the LLM system prompt for that turn only. The user never
  has to manually select a mode or click a button.

STAGE 2 — ChromaDB RAG Context Retrieval:
  Before sending to the cloud LLM, do a vector similarity search in the local
  ChromaDB for relevant chunks (resume bullets, job description, past Q&A pairs).
  Inject the top-3 results as grounding context into the LLM prompt so answers
  are personalized to the candidate's actual experience.

Both stages run LOCALLY and IN PARALLEL with each other (asyncio.gather).
Only the final assembled prompt is sent to the cloud LLM. Resume/JD data
never leave the machine.

STAGE 3: CHANGES — backend/app.py
═══════════════════════════════════════════════════════════════

In `ws_endpoint`, after receiving a complete, accepted transcript (post-smart-filter),
replace the existing LLM call block with this new pipeline:

```python
# --- Smart Context Pipeline ---

# 1. Run SmolLM2 classification + ChromaDB retrieval in parallel (local, fast)
if config.SMOLLM2_ENABLED:
    question_type, qa_context, resume_context = await asyncio.gather(
        asyncio.to_thread(local_intelligence.classify_question, transcript),
        asyncio.to_thread(qa_cache.retrieve_context, transcript),
        asyncio.to_thread(qa_cache.retrieve_resume_context, transcript),
    )
else:
    question_type = "conceptual"
    qa_context, resume_context = [], []

# 2. If noise, skip LLM entirely
if question_type == "noise":
    continue

# 3. Emit star_primed event to UI for behavioral questions (visual feedback)
if question_type == "behavioral":
    await websocket.send_json({"type": "star_primed"})

# 4. Build dynamic system prompt for this turn
turn_injection = local_intelligence.SYSTEM_PROMPT_INJECTIONS.get(question_type, "")
dynamic_system_prompt = base_system_prompt
if turn_injection:
    dynamic_system_prompt += f"\n\nFor this response: {turn_injection}"

# 5. Assemble RAG context block
context_chunks = []
if resume_context:
    context_chunks.append("Relevant background from candidate's profile:\n" + "\n".join(f"- {c}" for c in resume_context))
if qa_context:
    context_chunks.append("Related past answers from this session:\n" + "\n".join(f"- {c}" for c in qa_context))

if context_chunks:
    dynamic_system_prompt += "\n\n--- CONTEXT ---\n" + "\n\n".join(context_chunks)

# 6. Call cloud LLM with the enriched prompt
messages = [{"role": "system", "content": dynamic_system_prompt}] + conversation_history
response = await llm_client.chat(messages)
```

Key notes for implementation:
- `base_system_prompt` is the existing system prompt loaded from config.
- `conversation_history` is the existing rolling message list already in the ws_endpoint.
- The SmolLM2 call must use `asyncio.to_thread()` since llama_cpp is synchronous.
- Do NOT change the QA cache store logic — new answers should still be stored as before.
- Emit a `{"type": "question_type", "value": question_type}` WebSocket message so
  the frontend can optionally display a small badge (e.g. "🎭 Behavioral" or "💻 Coding").
