You are tasked with implementing Phase 81: "Candidate Send-to-LLM" — Two complementary features that let the candidate explicitly send their own spoken lines to the LLM for an AI response.

════════════════════════════════════════════════════════════════
BACKGROUND & CONTEXT
════════════════════════════════════════════════════════════════

Currently, the AI only auto-triggers on "interviewer" audio. This phase adds explicit user control
to send any "candidate" transcript line to the LLM, via:

  1. A Magic Wand hover button (🪄) on each candidate bubble in the transcript.
  2. A new global hotkey (Ctrl+Alt+S) that sends the LAST candidate line to the LLM.

════════════════════════════════════════════════════════════════
ARCHITECTURE OVERVIEW
════════════════════════════════════════════════════════════════

Key files:
- `wails-app/frontend/src/products/interview/ConvPanel.svelte`
  - Renders transcript bubbles. Each `item` has `{ role: string; text: string; answer?: string }`.
  - `item.role === 'candidate'` are the user's own spoken lines.
  - Bubbles have class `.bubble-candidate`.
  - The existing `onclick` on candidate bubbles adds text to input box (line ~247–262).

- `wails-app/app.go`
  - `AppendToBuffer(text string) error` — adds text to the rolling question buffer without flushing.
  - `FlushQuestionBuffer() error` — flushes buffer to LLM and triggers AI response.
  - These two called together = "send this text to the LLM and get a response".

- `wails-app/backend/hotkeys/hotkeys.go`
  - Uses `golang.design/x/hotkey` to register OS-level hotkeys.
  - Has `EventsEmit` var (mockable) to fire Wails events to the frontend.
  - Pattern to follow: `Ctrl+Alt+1` emits `"hotkey_transcript_1"` → frontend listens.
  - Has `NewHotkey` var (mockable) so tests can mock hotkey registration.

- `wails-app/frontend/src/lib/ws.svelte.ts`
  - Central Wails event listeners. The frontend already listens for `"hotkey_transcript_1"`.

- `wails-app/backend/buddy/index.html`
  - The friend's web interface. It also renders the transcript and should have the same wand button.

FEATURE 2: Global Hotkey Ctrl+Alt+S ("Send Last Candidate Line")
════════════════════════════════════════════════════════════════

─── Step A: Register the hotkey in `hotkeys.go` ───

Modify `wails-app/backend/hotkeys/hotkeys.go`:

1. Register a new hotkey: Ctrl+Alt+S
   ```go
   hkS := NewHotkey([]hotkey.Modifier{hotkey.ModCtrl, ModAlt}, hotkey.KeyS)
   if err := hkS.Register(); err != nil {
       log.Printf("⚠️  Failed to register Ctrl+Alt+S (send-to-LLM): %v\n", err)
       // Non-fatal: continue without this hotkey
   } else {
       log.Println("✅ Registered Ctrl+Alt+S (send last candidate line to LLM)")
   }
   ```

2. In the goroutine's select loop, add a case:
   ```go
   case <-hkS.Keydown():
       EventsEmit(ctx, "hotkey_send_candidate_to_llm")
   ```

3. In the ctx.Done() cleanup, add:
   ```go
   _ = hkS.Unregister()
   ```

─── Step B: Listen for the event in the Svelte frontend ───

Modify `wails-app/frontend/src/lib/ws.svelte.ts` (or wherever `hotkey_transcript_1` is listened to):

1. Add a listener for `"hotkey_send_candidate_to_llm"`.
2. The handler should:
   a. Find the LAST item in `transcriptHistory` (from wsState) where `item.role === 'candidate'`.
   b. If found, call `AppendToBuffer(item.text)` then `FlushQuestionBuffer()`.
   c. Emit a brief UI notification (optional toast or the button flash on the last wand button).

─── Step C: Add the hotkey to the Hotkeys panel ───

Somewhere in the UI (the existing Hotkeys tooltip/panel or `HotkeysModal.svelte`), document the new hotkey:
- `Ctrl+Alt+S` — Send last line to AI
