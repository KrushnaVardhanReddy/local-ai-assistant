TASK: P14-T1 — Transcript Chip Bar (Click-to-Send Pending Transcripts)

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Add a clickable transcript chip bar between the top toolbar and the main content
panels. As the backend streams live transcripts (type "transcript" messages),
the frontend accumulates them as visual "chips" — short rounded pill buttons
showing the transcribed text. Clicking a chip immediately sends that text to
the LLM as a priority question (using the existing "chat" bypass), skipping
all audio filter layers.

This gives the user manual control over which heard phrases to send to the LLM,
complementing the existing automatic silence-detection flow. The auto-flow
continues to work unchanged — the chip bar is an additional layer on top.

Key behaviors:
  1. Incoming "transcript" WS messages are accumulated into a chip array
     (max 6 chips, oldest dropped when full).
  2. Each chip displays the first 60 characters of the transcript, truncated
     with "…" if longer.
  3. Clicking a chip sends it as a `{ type: "chat", text: fullText }` message
     via the existing `sendChat()` function, then removes the chip from the bar.
  4. A small "×" button on each chip dismisses it without sending.
  5. A "Clear" button at the right end of the chip bar clears all pending chips.
  6. When the LLM starts responding (message_start), all chips are auto-cleared
     since the auto-flow handled it.
  7. The chip bar is hidden when there are zero chips (no empty bar visible).
  8. Chips have a subtle entrance animation (fade + slide up).

CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- All changes are FRONTEND ONLY. Do NOT modify any backend files.
- Use Svelte 5 runes ($state, $effect) — NOT Svelte 4 stores.
- The chip bar must use the same glassmorphism design language as the existing
  toolbar and panels (see .glass-pill and .glass-panel in Assistant.svelte).
- Chips must be pointer-events-auto so they are clickable on the overlay.
- The chip bar must respect the existing layout: it sits BETWEEN the <header>
  toolbar and the <main> content grid, inside the same outer flex-col container.
- Do NOT break any existing functionality: transcript display in Live Ears panel,
  LLM response in The Brain panel, PTT, vision capture, chat input, drag-to-move,
  stealth hotkeys, or the hide/close buttons.
- Deduplication: If a new transcript is identical to an existing chip's text,
  replace the old chip (update in place) rather than adding a duplicate.
- The chip bar must work in both Tauri desktop mode AND browser (Remote Helper)
  mode.

CONTEXT — EXISTING REPO LAYOUT & ARCHITECTURE
═══════════════════════════════════════════════════════════════
- `frontend/src/lib/ws.svelte.ts`: Reactive WebSocket store using Svelte 5 runes.
  - `wsState` is a `$state({...})` object with fields: transcript, response,
    isListening, isThinking, isConnected, error, ragSources, isPTTHeld, pttMode.
  - `sendChat(text: string)` sends `{ type: "chat", text }` over the WebSocket.
    Chat messages bypass ALL backend filter layers (silence buffer, busy guard,
    intent heuristic) and go directly to the LLM. This is the function to use
    when the user clicks a chip.
  - The `ws.onmessage` handler dispatches on `data.type`:
    - "transcript" → sets `wsState.transcript` to the latest live transcript
    - "message_start" → clears response, sets isThinking
    - "token" → appends to wsState.response
    - "end" → clears isThinking

  Layout structure (important — do NOT break this):


- Styling: The component uses Tailwind utility classes + custom CSS at the bottom.
  The glassmorphism style is defined in `.glass-pill` and `.glass-panel` classes.

   a. Add a new reactive field to `wsState` for the chip queue:
      ```typescript
      pendingTranscripts: [] as Array<{ id: number; text: string }>
      ```

   b. Add a module-level counter for unique chip IDs:
      ```typescript
      let chipIdCounter = 0;
      ```

   c. In the `ws.onmessage` handler, inside the "transcript" case, AFTER the
      existing `wsState.transcript = data.text;` line, add logic to accumulate
      chips:
      ```typescript
      case "transcript":
        wsState.transcript = data.text;
        // Accumulate as a clickable chip (deduplicate identical text)
        const existingIdx = wsState.pendingTranscripts.findIndex(
          (c) => c.text === data.text
        );
        if (existingIdx >= 0) {
          // Update in place (keeps position, refreshes)
          wsState.pendingTranscripts[existingIdx] = {
            id: wsState.pendingTranscripts[existingIdx].id,
            text: data.text
          };
        } else {
          wsState.pendingTranscripts.push({
            id: chipIdCounter++,
            text: data.text
          });
          // Keep max 6 chips — drop oldest
          if (wsState.pendingTranscripts.length > 6) {
            wsState.pendingTranscripts.shift();
          }
        }
        break;
      ```

   d. In the "message_start" case, clear the chip queue (the auto-flow handled it):
      ```typescript
      case "message_start":
        wsState.response = "";
        wsState.isThinking = true;
        wsState.ragSources = [];
        wsState.pendingTranscripts = [];   // ← ADD THIS LINE
        break;
      ```

   e. In the existing `panic-clear` listener, also clear the chip queue:
      ```typescript
      listen("panic-clear", () => {
        wsState.transcript = "";
        wsState.response = "";
        wsState.isThinking = false;
        wsState.ragSources = [];
        wsState.pendingTranscripts = [];   // ← ADD THIS LINE
        ...
      });
      ```

   f. Export two new helper functions for chip actions:
      ```typescript
      export function sendChip(chip: { id: number; text: string }): void {
        sendChat(chip.text);
        wsState.pendingTranscripts = wsState.pendingTranscripts.filter(
          (c) => c.id !== chip.id
        );
      }

      export function dismissChip(chipId: number): void {
        wsState.pendingTranscripts = wsState.pendingTranscripts.filter(
          (c) => c.id !== chipId
        );
      }

      export function clearAllChips(): void {
        wsState.pendingTranscripts = [];
      }
      ```

═══════════════════════════════════════════════════════════════
IMPLEMENTATION HINTS
═══════════════════════════════════════════════════════════════
- The `sendChat()` function already sends `{ type: "chat", text }` over the
  WebSocket, which bypasses ALL backend filter layers. No backend changes needed.
- Use `{#each ... as chip (chip.id)}` with a keyed each block so Svelte can
  animate individual chips correctly.
- The chip bar uses `overflow-x-auto` + `hide-scrollbar` (already defined in
  Assistant.svelte CSS) for horizontal scrolling when there are many chips.
- The `flex-shrink-0` on individual chips prevents them from being crushed
  when the bar overflows.
- In Svelte 5, use `onclick={(e) => { e.stopPropagation(); ... }}` instead of
  the Svelte 4 `on:click|stopPropagation` syntax.
- The `max-w-[200px] truncate` on the chip text ensures long transcripts don't
  make chips too wide. The full text is available in the `title` attribute.
