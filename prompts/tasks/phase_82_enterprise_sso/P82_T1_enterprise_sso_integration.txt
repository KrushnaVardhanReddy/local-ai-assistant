════════════════════════════════════════════════════════════════

─── STEP 1: Implement the Auth Store ───
Create `wails-app/frontend/src/lib/authStore.ts`:
1. Use Svelte 5 runes (`$state`) to track the authentication status.
2. Track `isAuthenticated` (boolean), `userEmail` (string), and `licenseType` (string - 'pro' | 'enterprise').
3. For this phase, we will mock the backend validation. Provide a `login(email, token)` and `logout()` method.

─── STEP 2: Create the Enterprise Auth Modal ───
Create `wails-app/frontend/src/lib/EnterpriseAuth.svelte`:
1. This should be a blocking, full-screen modal (similar to LegalModal) that prevents use of the app until authenticated.
2. The UI should look premium and corporate. Title: "BarnOwl AI Enterprise Login".
3. Provide an input for "Work Email" and a "Continue with SSO" button.
4. When the user clicks "Continue with SSO", simulate a brief loading state, then validate the email domain. If the domain is `@mckinsey.com`, `@bcg.com`, or `@bain.com` (for testing purposes), authenticate them and set the store state. Otherwise, show an error: "No active enterprise license found for this domain."

─── STEP 3: Wire Auth into App.svelte ───
Modify `wails-app/frontend/src/App.svelte`:
1. Import `EnterpriseAuth.svelte` and `authStore.ts`.
2. Wrap the main application UI components in an `{#if authStore.isAuthenticated}` block.
3. If NOT authenticated, render the `<EnterpriseAuth />` component over everything.
4. Ensure the `LegalModal` is only shown AFTER successful authentication.
