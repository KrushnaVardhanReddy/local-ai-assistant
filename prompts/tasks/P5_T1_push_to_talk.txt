TASK: P5-T1 — Global Push-to-Talk Hotkey

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Implement a global push-to-talk (PTT) system: hold `Ctrl+Shift+P` to capture mic
audio, release to transcribe. Works even when the app window is hidden. The
backend switches between always-on and PTT modes based on a config flag.

═══════════════════════════════════════════════════════════════
CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- PTT hotkey (`Ctrl+Shift+P`) must NOT conflict with the show/hide hotkey (`Ctrl+Shift+Space`) from P4-T5.
- In always-on mode (default), PTT is disabled — the mic runs continuously.
- In PTT mode (`PTT_MODE=true` env var), the mic only captures while the hotkey is held.
- The backend must support both modes without restart — toggle via `POST /ptt/mode`.
- Repeat key events (key held down) must be ignored — only the first keydown and keyup fire.

═══════════════════════════════════════════════════════════════
IMPLEMENTATION HINTS
═══════════════════════════════════════════════════════════════
- Tauri 2.0 shortcut events do not distinguish press vs. release by default. Use `ShortcutState::Pressed` and `ShortcutState::Released` from the `tauri_plugin_global_shortcut::ShortcutEvent` to differentiate — check the event state field.
- `threading.Event.clear()` is not the same as `threading.Event.set()` — `clear()` makes `is_set()` return False (blocking), `set()` makes it True (unblocked). Verify the pause/resume semantics match the naming.
- The audio queue may contain pre-PTT chunks when PTT is engaged. Call `queue.Queue.queue.clear()` (access the internal deque) or drain it with `while not q.empty(): q.get_nowait()` in `pause()` to discard buffered audio from before the key press.
