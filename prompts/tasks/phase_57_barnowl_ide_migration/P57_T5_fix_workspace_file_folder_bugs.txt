TASK: P57-T5 — Fix Real-World BarnOwl Workspace File/Folder Explorer & IDE Wiring

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Fix critical real-world workspace file and folder bugs in BarnOwl AI (Interview Copilot)
where clicking the ActivityBar "Folder" icon, "FILE", and "FOLDER" buttons fails to open
folders or files, the folder tree does not expand, and code files are rejected by the engine.

All previous Playwright E2E tests passed only because they relied on a shallow mock that
completely bypassed the actual UI event handlers and data models. This task fixes the
underlying frontend and backend bugs and replaces shallow assertions with realistic web E2E tests.

═══════════════════════════════════════════════════════════════
BEHAVIOR & BUTTON EXPECTATIONS
═══════════════════════════════════════════════════════════════

1. [Folder / Explorer Icon] (Left ActivityBar - `id: 'explorer'`):
   - Expected: Clicking this icon toggles the WorkspaceSidebar drawer open (`width: 240px`)
     and closed (`width: 0px`).
   - Bug in current code: `InterviewHUD.svelte`'s `handleAction(action)` intercepts `'explorer'`
     and only sets `activeAction = 'explorer'`, but does NOT update `IDEShell.svelte`'s internal
     `isExplorerOpen` state. Thus, the sidebar drawer stays permanently closed (0px wide).

2. [FILE Button] (Workspace Sidebar Header - `onOpenFile`):
   - Expected: Clicking "FILE" opens the native file dialog (`App.PromptOpenFile()`), loads the
     selected file into the engine, opens it in a new tab in `WorkspaceTabs.svelte`, selects it,
     and immediately displays its content in `CodeEditor.svelte`.
   - Bug in current code: After `PromptOpenFile()` resolves, the UI waits up to 1000ms for a
     passive polling tick instead of immediately refreshing state with `GetIDEState()`.

3. [FOLDER Button] (Workspace Sidebar Header - `onOpenFolder`):
   - Expected: Clicking "FOLDER" opens the native directory dialog (`App.PromptOpenDirectory()`),
     indexes the folder's files and subdirectories, displays the hierarchical file tree in
     `FileTree.svelte`, and immediately refreshes the UI.
   - Bug in current code: Waits for passive polling, and fails to load directories containing code!

4. [File & Folder Tree Nodes] (`FileTreeNode.svelte`):
   - Expected: Folders can be expanded/collapsed by clicking them or pressing Enter/Space.
     Clicking a file node opens that document in the editor and switches the active tab.
   - Bug in current code:
     a) Go backend (`driving.FileNode`) serializes `isDir: bool`, but Svelte components
        (`types.ts`, `FileTreeNode.svelte`, `FileTree.svelte`) check `node.isDirectory`.
        Because `InterviewHUD.svelte` does not normalize `isDir` -> `isDirectory`, every node is
        treated as a file; folders have no chevron, cannot expand, and show broken file icons!
     b) In `InterviewHUD.svelte`, `handleSelectNode(node)` checks `!node.is_dir`, but does not check
        `!node.isDirectory`, causing click handling to fail depending on object keys.

5. [Allowed File Extensions] (`wails-app/core/engine/workspace.go`):
   - Expected: When a user opens a folder or project with interview notes, cheat sheets, or code
     (e.g., Python scripts, Go files, TypeScript/JavaScript, markdown, json, etc.), the engine
     indexes them.
   - Bug in current code: `allowedExtensions` is strictly limited to `.txt`, `.md`, `.pdf`, `.pptx`.
     Opening any folder containing code files logs:
     "directory ... does not contain valid document files" and completely drops the folder!

2. Fix Tree Normalization & Expansion State in `InterviewHUD.svelte`:
   - Implement tree mapping that normalizes `isDir` -> `isDirectory` and preserves expanded folders
     across polling cycles:
     ```ts
     const expandedMap = new Map<string, boolean>();
     function recordExpanded(nodes: any[]) {
       for (const n of nodes) {
         if ((n.isDirectory || n.isDir) && n.isExpanded !== undefined) {
           expandedMap.set(n.path, n.isExpanded);
         }
         if (n.children) recordExpanded(n.children);
       }
     }

     function mapTree(nodes: any[]): any[] {
       if (!nodes) return [];
       return nodes.map((n: any) => {
         const isDir = Boolean(n.isDirectory ?? n.isDir);
         return {
           ...n,
           isDirectory: isDir,
           isDir: isDir,
           isExpanded: expandedMap.has(n.path) ? expandedMap.get(n.path) : (n.isExpanded ?? false),
           children: mapTree(n.children)
         };
       });
     }
     ```
   - In `refreshIDEState()` / `statePollInterval`:
     ```ts
     recordExpanded(workspaceTree);
     workspaceTree = mapTree(state.workspaceTree);
     ```
