TASK: P57-T6 — LLM Stream Preemption, Interruption Handling & Non-Blocking Utterance Pipeline

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Replace the strict, blocking mutex lock in `wails-app/core/engine/pipeline.go` (`e.llmBusy.TryLock()`)
with an interruptible, non-blocking LLM execution pipeline using Go contexts (`context.WithCancel`).

When an interviewer interrupts or asks a follow-up question while the LLM is still streaming tokens:
1. The engine MUST cancel the previous in-flight HTTP request cleanly (`cancel()`).
2. The engine immediately begins streaming the response for the new question.
3. If an utterance is detected as a secondary phrase/topic, emit it as a suggestion chip to `on_chip` so it is never dropped into `/dev/null`.
4. Add comprehensive Go unit tests verifying preemption, context cancellation, and zero deadlocks.

═══════════════════════════════════════════════════════════════
CURRENT PROBLEM & ROOT CAUSE
═══════════════════════════════════════════════════════════════
In `wails-app/core/engine/pipeline.go`:
```go
if !e.llmBusy.TryLock() {
    log.Printf("[BUSY] Discarded (LLM streaming): %q", cleanTranscript)
    return
}
```
If an interviewer starts asking a real question like:
"How do you pass data between the go routines?"
while an earlier stream is generating tokens, the question is completely DISCARDED.
The user never gets an answer, and no HTTP call is made.

═══════════════════════════════════════════════════════════════
EXACT IMPLEMENTATION SPECIFICATION (GO COMPILER SAFE)
═══════════════════════════════════════════════════════════════

1. StealthEngine Struct Fields in `wails-app/core/engine/engine.go`:
   - Do NOT compare `context.CancelFunc` directly (in Go, `func` values are uncomparable and cause compile errors).
   - Use an incrementing `currentStreamID uint64` to identify and manage active streams:
     ```go
     // In StealthEngine struct:
     inFlightMu       sync.Mutex
     cancelInFlight   context.CancelFunc
     currentStreamID  uint64
     ```
   - In `ClearState()`:
     ```go
     e.inFlightMu.Lock()
     if e.cancelInFlight != nil {
         e.cancelInFlight()
         e.cancelInFlight = nil
     }
     e.inFlightMu.Unlock()
     ```

2. Preemption & Pipeline Execution in `wails-app/core/engine/pipeline.go`:
   - Replace the `e.llmBusy.TryLock()` discard block with stream preemption:
     ```go
     e.inFlightMu.Lock()
     if e.cancelInFlight != nil {
         log.Printf("[PREEMPT] Interrupting in-flight LLM stream for new question: %q", cleanTranscript)
         e.cancelInFlight()
     }
     e.currentStreamID++
     streamID := e.currentStreamID
     ctx, cancel := context.WithCancel(context.Background())
     e.cancelInFlight = cancel
     e.inFlightMu.Unlock()
     ```
   - Pass `ctx context.Context` into `e.llm.StreamCompletion(ctx, ...)` or update `ports/driven/llm.go` LLMPort interface to accept `ctx context.Context`.
   - In the streaming completion goroutine, ensure cleanup checks `streamID`:
     ```go
     defer func() {
         e.inFlightMu.Lock()
         if e.currentStreamID == streamID {
             e.cancelInFlight = nil
         }
         e.inFlightMu.Unlock()
     }()
     ```
   - Also update `wails-app/backend/llm/openai.go` to use `http.NewRequestWithContext(ctx, "POST", ...)` so that calling `cancel()` immediately aborts the active HTTP TCP socket without waiting for the timeout.

3. Suggestion Fallback (`on_chip`):
   - Whenever an utterance is received, if it is not immediately answered or if it represents an alternative option, emit:
     ```go
     if e.events != nil {
         e.events.Emit("on_chip", map[string]interface{}{
             "id":   fmt.Sprintf("chip_%d", time.Now().UnixNano()),
             "text": cleanTranscript,
         })
     }
     ```

4. Go Unit Tests & Mock Visibility in `wails-app/core/engine/`:
   - Place tests in `wails-app/core/engine/pipeline_test.go`.
   - Ensure the package matches `package engine` or `package engine_test` consistently.
   - If in `package engine_test`, export or define mocks (`MockLLM`, `MockCache`, `MockEvents`) in a shared `mocks_test.go` or directly in `pipeline_test.go`.
   - Write 3 robust unit tests:
     1. `TestPipeline_PreemptionOnInterruption`: Send Question 1 with a slow mock LLM, then send Question 2 immediately. Verify Question 1's context is canceled and Question 2 streams its response.
     2. `TestPipeline_ClearStateCancelsInFlight`: Start streaming, call `ClearState()`, and verify the context is canceled and `e.cancelInFlight` is nil.
     3. `TestPipeline_EmitsOnChip`: Verify that received transcripts emit `on_chip` events so questions are never lost.
