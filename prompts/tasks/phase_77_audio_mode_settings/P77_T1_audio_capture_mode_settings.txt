You are tasked with wiring the Audio Capture Mode selector into the Settings UI. This is Phase 77, Task 1 (P77-T1).

════════════════════════════════════════════════════════════════
TASK CONTEXT
════════════════════════════════════════════════════════════════

BarnOwl AI already has two fully-implemented audio capture engines in the Go backend:

1. **Interview Mode** (`AppModeInterview`): Uses `CaptureEngine` to capture only system audio
   (loopback — i.e., the interviewer's voice coming through Google Meet / Zoom / Teams).
   Audio is tagged `[Interviewer]`. The user's own microphone is silent. Best for stealth.

2. **Transcript Mode** (`AppModeTranscript`): Uses `DualCaptureEngine` to capture BOTH the
   loopback audio AND the microphone simultaneously. Both streams are transcribed, tagged as
   `[Interviewer]` and `[Candidate]` respectively, giving a complete two-sided conversation log.

These modes are already toggled by the `SetAppMode(mode string)` Wails-bound method in `app.go`.
The `wsState.appMode` in `ws.svelte.ts` and the `setAppMode()` export already exist and work.

There is currently NO UI in Settings to let the user switch between these modes during a session.
This task adds that UI — it is a surgical, single-file Svelte change.

────────────────────────────────────────────────────────────────
IMPORTANT NOTES
────────────────────────────────────────────────────────────────

- The `setAppMode()` function is ALREADY exported from `ws.svelte.ts`. It handles all the backend
  communication and localStorage persistence internally. You do NOT need to call `handleSaveSettings()`
  for this — it takes effect immediately when the radio button is clicked.
- Do NOT add this to the `handleSaveSettings()` function — mode switching is instant.
- Do NOT use Svelte's `bind:group` for the radio buttons. Use `checked={...}` and `onchange`
  explicitly, as shown above, to avoid Svelte 5 reactivity issues with `$state`.
- The `wsState.appMode` will update reactively via `$state` and the radio buttons will reflect
  the current mode without needing any additional local state.
