TASK: P67-T4 — Conversational Context Window (Rolling Turn Memory)
════════════════════════════════════════════════════════════════

OBJECTIVE:
Fix a critical UX failure in BarnOwl AI: when an interviewer asks a follow-up question
like "Why?", "Explain that further", or "Give me an example of that", the AI currently
has NO memory of the previous question or answer. It responds incorrectly because it has
zero context about what "that" or "why" refers to.

This task adds a Conversational Context Window to the LLM prompt builder. It reads the
last 3 completed turns from the existing SessionManager, formats them as a compact
context block, and prepends that block to every outgoing LLM prompt. This is a pure
backend change — no frontend changes required.

PREREQUISITE: None. This task is INDEPENDENT of P67-T1, T2, T3 and can run in parallel.

─── CHANGES TO wails-app/backend/llm/prompts.go ────────────────────────────────

1. Add import for "wails-app/backend/session" and "fmt" and "strings" if not already present.

2. Add constant:
   const MaxContextTurns = 3
   const MaxContextTokensApprox = 400  // ~400 words, safe for all supported cloud models

3. Add new function: BuildContextBlock(turns []session.Turn) string
   - If len(turns) == 0, return "" (empty string — no context to inject).
   - Build a formatted string representing the last N completed turns.
   - Use this EXACT format for each turn (very compact, token-efficient):
   
     [Turn N] Interviewer: "<InterviewerQuestion truncated to 120 chars>"
              AI Answer:   "<AISuggestion truncated to 200 chars>"
   
   - Truncation rule: if a field exceeds its character limit, slice it and append "..."
   - Wrap the block like this:
   
     === Recent Interview Context (last N turns) ===
     [Turn 1] Interviewer: "..."
              AI Answer:   "..."
     [Turn 2] ...
     === End Context ===
   
   - After building the block, count its total characters. If it exceeds 2000 characters
     (a proxy for ~400 tokens), trim turns from the oldest end until it fits.
   - Return the final formatted block string.

4. MODIFY BuildSystemPrompt(category string) string → rename to BuildSystemPrompt and
   keep its current signature. DO NOT change its existing logic.

5. ADD new function: BuildFullSystemPrompt(category string, turns []session.Turn) string
   - Calls BuildSystemPrompt(category) to get the base prompt.
   - Calls BuildContextBlock(turns) to get the context block.
   - If contextBlock is empty, return the base prompt unchanged.
   - If contextBlock is non-empty, return:
     basePrompt + "\n\n" + contextBlock
   This is the function the LLM call site will use instead of BuildSystemPrompt directly.

─── CHANGES TO THE LLM CALL SITE ────────────────────────────────────────────────

Find the exact location in the codebase where:
  a) BuildSystemPrompt(category) is called, AND
  b) The LLM request (StreamCompletion or equivalent) is initiated with a question string.

At that call site:
  1. Get the SessionManager (it is already stored in the engine struct — find it).
  2. Call: recentTurns := sessionManager.GetRecentTurns(MaxContextTurns)
  3. Replace: llm.BuildSystemPrompt(category)
     With:    llm.BuildFullSystemPrompt(category, recentTurns)

That is the ONLY change required at the call site. All the formatting logic lives in prompts.go.
