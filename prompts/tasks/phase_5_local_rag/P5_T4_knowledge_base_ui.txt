TASK: P5-T4 — Knowledge Base UI (Drag-and-Drop Upload + Source Display)

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Add a "Knowledge Base" tab to the Tauri desktop app's settings panel. Users can
drag-and-drop or click-to-select PDF/TXT/MD files to upload them to the local RAG
backend. The assistant overlay also shows which source files informed each response.

═══════════════════════════════════════════════════════════════
CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- File upload must use `fetch("http://127.0.0.1:{port}/rag/upload", { method: "POST", body: FormData })` — NOT the Tauri FS plugin (backend handles the file).
- Only accept `.pdf`, `.txt`, `.md` — validate client-side before upload and reject others with inline error.
- Show a per-file upload progress indicator (use `XMLHttpRequest` with `upload.onprogress` for accurate progress — `fetch` API doesn't expose upload progress).
- After upload, refresh the document list from `GET /rag/documents` automatically.
- The "Sources" citation display in the assistant must work with the existing `rag_sources` WS message type from P5-T3.

═══════════════════════════════════════════════════════════════

═══════════════════════════════════════════════════════════════

- `frontend/src/lib/ws.ts` (P4-T2): Already dispatches messages by `type`. Add handler: `if (data.type === "rag_sources") { ragSources = data.sources }`.
- `frontend/src/lib/Settings.svelte` (P6-T1 in new numbering): Add a "Knowledge Base" tab section. If Settings doesn't exist yet, create `KnowledgeBase.svelte` as a standalone component and integrate it in `App.svelte`.
- Backend endpoints available: `POST /rag/upload`, `GET /rag/documents`, `DELETE /rag/document/{filename}`.
- Design tokens: same as the rest of the app — `#0d0d0d` background, `rgba(255,255,255,0.04)` surface, `#7c3aed` accent.

DELIVERABLES
═══════════════════════════════════════════════════════════════

1. FILE: frontend/src/lib/KnowledgeBase.svelte (CREATE)
   Sections in order:
   a. **Drop zone** (full-width dashed bordered box, `~200px` height):
      - Text: "Drop PDF, TXT, or MD files here, or click to browse"
      - On `dragover`: border turns purple (`#7c3aed`), slight glow effect.

      - On success: add file to document list, remove from queue after 2s.
   c. **Ingested documents list**:
      - Fetched on component mount from `GET /rag/documents`.
      - One row per file: 📄 icon + filename + "Delete" button (calls `DELETE /rag/document/{filename}`, then refreshes list).
      - Empty state: "No documents ingested yet. Upload your first file above."
   d. **RAG toggle**:
      - A toggle switch labeled "Use knowledge base for responses".
      - Calls `POST /rag/toggle` (add this endpoint to `app.py` — sets `config.RAG_ENABLED` at runtime).
      - Reads current state from `GET /rag/status` on mount.

═══════════════════════════════════════════════════════════════
IMPLEMENTATION HINTS
═══════════════════════════════════════════════════════════════
- `dragover` and `dragleave` events don't bubble reliably in Svelte — bind them directly on the drop zone `<div>`, not on a parent. Use `event.preventDefault()` in `dragover` to allow the drop.
- `XMLHttpRequest` is not deprecated — it's the ONLY way to track upload progress in browsers. Use it here, even though the rest of the app uses `fetch`.
- `config.RAG_ENABLED` is a module-level variable in Python. In-place mutation (`config.RAG_ENABLED = not config.RAG_ENABLED`) works because the FastAPI route and the `app.py` pipeline code read from the same module object. No restart needed.
