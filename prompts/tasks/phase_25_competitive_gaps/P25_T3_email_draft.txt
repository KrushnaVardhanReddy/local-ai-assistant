TASK: P25-T3 — Post-Interview Email Draft (Competitive Gap vs Cluely)

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Add an "Email Draft" section to the existing SessionReport.svelte
component. After the session scorecard is loaded, the user can click
"Draft Follow-Up Email" to generate a professional post-interview
thank-you / follow-up email based on the session transcript and
scorecard. The draft is rendered in an editable textarea and can be
copied to clipboard with one click.

This closes a key gap vs Cluely, which auto-generates follow-up emails
from meeting context. Our version is interview-specific and uses the
scorecard as source data — making it more personalized than Cluely's
generic templates.

Key behaviors:
  1. In SessionReport.svelte, after the scorecard section, show a
     "Draft Follow-Up Email" button.
  2. When clicked, send a POST request to the NEW backend endpoint
     `POST /session/email-draft` which generates the email via LLM.
  3. The generated email renders in a styled `<textarea>` (editable,
     so the user can tweak it before sending).
  4. A "Copy Email" button copies the draft to clipboard.
  5. The generated email should be a professional 3-paragraph thank-you
     email: opens with gratitude, references a specific topic from the
     session, closes with enthusiasm about the role.
  6. Show a loading spinner while generating (separate from the scorecard
     loading state — the email is generated on demand, not on load).

   Add the following new Pydantic model and endpoint AFTER the existing
   `/session/clear` endpoint (after line 1081), before the
   `InternalPlanUpdateModel` class:

   a. Add Pydantic request model:
      ```python

          session: dict
          scorecard: dict
          interviewer_name: str = ""
          company_name: str = ""
          role_name: str = ""
      ```

   b. Add the endpoint:
      ```python
      @app.post("/session/email-draft")
      async def generate_email_draft(body: EmailDraftRequest):
          """Generate a post-interview follow-up email using the session scorecard."""
          if not body.session or not body.scorecard:
              return JSONResponse({"error": "Session data required"}, status_code=400)

          # Build a concise summary for the prompt
          strengths = ", ".join(body.scorecard.get("strengths", [])[:3]) or "my technical responses"
          topics = []
          for turn in body.session.get("turns", [])[:5]:
              q = turn.get("question", "")
              if q:
                  topics.append(q[:80])
          topic_str = topics[0] if topics else "the technical topics we discussed"

          interviewer = body.interviewer_name or "the interviewer"
          company = body.company_name or "your company"
          role = body.role_name or "the role"

          prompt = (
              f"Write a concise, professional post-interview thank-you email.\n"
              f"Interviewer: {interviewer}\n"
              f"Company: {company}\n"
              f"Role: {role}\n"
              f"Key topic discussed: {topic_str}\n"
              f"Candidate's strengths shown: {strengths}\n\n"
              f"Requirements:\n"
              f"- 3 short paragraphs only\n"
              f"- Para 1: Thank them and express enthusiasm for the role\n"
              f"- Para 2: Reference a specific topic from the interview to show engagement\n"
              f"- Para 3: Reiterate interest and next steps\n"
              f"- Tone: warm, professional, confident — NOT sycophantic\n"
              f"- Subject line at the very top (format: Subject: ...)\n"
              f"- Plain text only, no markdown\n"
              f"Output ONLY the email (subject + body). No preamble."
          )

          if not llm_client:
              return JSONResponse({"error": "LLM client not initialized"}, status_code=503)

          try:
              messages = [{"role": "user", "content": prompt}]
              email_text = await llm_client.chat_complete(messages)
              return JSONResponse({"email": email_text})
          except Exception as e:
              return JSONResponse({"error": str(e)}, status_code=500)
      ```

   IMPORTANT: Check if `llm_client.chat_complete()` exists. If the
   LLMClient class only has `stream_tokens()`, implement the endpoint
   using `stream_tokens()` and accumulate the full string before returning:
   ```python
   full_text = ""

       full_text += token
   ```

   b. Add the email generation function (after `copyToClipboard()`):
      ```typescript
      async function generateEmailDraft() {
        if (!session || !scorecard) return;
        isGeneratingEmail = true;
        emailError = null;
        try {
          const resp = await fetch("http://127.0.0.1:8765/session/email-draft", {
            method: "POST",
            headers: { "Content-Type": "application/json" },
            body: JSON.stringify({
              session,
              scorecard,
              interviewer_name: interviewerName,
              company_name: companyName,
              role_name: roleName,
            }),
          });
          if (!resp.ok) {
            const data = await resp.json();
            emailError = data.error || "Failed to generate email";
            return;
          }
          const data = await resp.json();
          emailDraft = data.email;
        } catch (e) {
          emailError = "Could not connect to backend";
        } finally {
          isGeneratingEmail = false;
        }
      }

      function copyEmail() {
        if (emailDraft) navigator.clipboard.writeText(emailDraft);
      }
      ```

IMPLEMENTATION HINTS
═══════════════════════════════════════════════════════════════
- The email textarea uses `bind:value={emailDraft}` making it editable —
  the user can tweak the draft before copying. This is intentional.
- The "Regenerate" button sets emailDraft = null, which hides the textarea
  and shows the "Draft Follow-Up Email" button again.
- Material Symbols `mail` and `auto_awesome` and `content_copy` and
  `progress_activity` are all already loaded in the app via the existing
  Google Fonts Material Symbols import.
- The optional metadata (interviewer name, company, role) improves email
  quality but is NOT required — the LLM uses sensible fallbacks.
- The "Add details ▼" toggle keeps the UI clean by default.
- The `secondary` color in the button (`text-secondary`, `bg-secondary/10`)
  matches the teal/green palette established in the app, distinguishing
  this feature from the primary (blue) action buttons.
- If llm_client.chat_complete() does not exist, use stream_tokens() and
  accumulate as described in the backend deliverable note above.
