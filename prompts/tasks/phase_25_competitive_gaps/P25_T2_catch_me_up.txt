TASK: P25-T2 — "Catch Me Up" Button (Competitive Gap vs Cluely)

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Add a "Catch Me Up" feature — a button that, when clicked, asks the LLM
to summarize everything said in the last N transcript turns so the user
can quickly recover context after dropping focus during a meeting or
interview.

This is Cluely's #1 differentiating feature. The implementation is
simple: it reads the accumulated transcript history from the Live Ears
panel and sends a summary request to the LLM via the existing sendChat()
pipeline.

Key behaviors:
  1. A "⏪ Catch Up" button appears in The Brain panel header (right side),
     next to the existing collapse button.
  2. When clicked, it sends a chat message to the LLM:
     "Here is the conversation so far. Give me a concise 3-5 bullet
      summary of what has been discussed: [transcript history]"
  3. The transcript history used is `wsState.transcriptHistory` — a new
     rolling buffer of the last 10 transcript strings we will add to
     wsState in ws.svelte.ts.
  4. If there is no history yet, show a brief error:
     "No conversation history yet — start speaking first."
  5. The button shows a loading spinner while the LLM is responding
     (wsState.isThinking is true).
  6. The button is disabled while wsState.isThinking is true.

      function triggerCatchMeUp() {
        if (wsState.isThinking) return;
        const history = wsState.transcriptHistory;
        if (!history || history.length === 0) {
          wsState.error = "No conversation history yet — start speaking first.";
          setTimeout(() => { wsState.error = null; }, 3000);

          .map((t, i) => `${i + 1}. "${t}"`)
          .join("\n");
        sendChat(
          `Here is the conversation transcript so far:\n${historyText}\n\n` +

IMPLEMENTATION HINTS
═══════════════════════════════════════════════════════════════
- The `transcriptHistory` is a client-side rolling buffer. It does NOT
  need to be persisted to the backend — it lives only for the current
  WebSocket session.
- Use Material Symbols icon `history` (a clock with an arrow) for the
  Catch Up button. This is already loaded in the app.
- The button is disabled when isThinking (LLM busy) or when there's no
  history yet — both indicated by muted color and `cursor-not-allowed`.
- The LLM prompt deliberately says "3-5 bullet points" to keep the
  summary short and scannable during an active interview.
- Deduplication (checking `last !== data.text`) prevents the same
  sentence being stored multiple times when the STT backend streams
  the same partial transcript multiple times.
