We need to implement the `ParakeetEngine` that uses `sherpa-onnx` and hook it into the manager once the download finishes.

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
1. PARAKEET ENGINE (`wails-app/backend/stt/parakeet.go`)
   - Create `type ParakeetEngine struct` that implements `STTEngine`.
   - **CRITICAL CGO FIX:** Since the `sherpa-onnx` DLLs are downloaded at *runtime* (P46-T2), standard compile-time CGO linking will fail. You must dynamically load the shared library at runtime.
   - Use `github.com/ebitengine/purego` (or `syscall.LoadLibrary` / `syscall.NewLazyDLL` on Windows and `plugin` on Linux) to dynamically load the downloaded `sherpa-onnx` C-API functions without requiring the library at compile time.
   - Ensure the path logic correctly points to `~/.local/share/barnowl/models/` to find the `.dll`, `.so`, or `.dylib`.

2. HOT-SWAP LOGIC
   - Modify the downloader from P46-T2 so that when the zip extraction completes, it automatically calls `STTManager.SwapEngine(NewParakeetEngine())`.

3. COMPREHENSIVE UNIT TESTS
   - You MUST create `parakeet_test.go`.
   - Since the DLLs won't be present on CI, design the tests to skip gracefully or mock the CGO boundary if the DLLs are missing.
