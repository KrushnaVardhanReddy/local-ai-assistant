TASK: P4-T4 — Root App Component (App.svelte)

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Replace the scaffold placeholder App.svelte with the root component that mounts
the Assistant overlay, connects to the WebSocket backend on startup, and renders
the mic status indicator. This component is the entry point for all UI state.

═══════════════════════════════════════════════════════════════
CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- Use Svelte 5 lifecycle: `onMount`, `onDestroy` — NOT Svelte 4 patterns.
- The root element must be `width:100vw; height:100vh; background:transparent` — the Tauri window handles the actual transparent frame.
- Do NOT hardcode the WebSocket URL — it comes from `$lib/ws` which reads `VITE_WS_URL`.
- `connect()` must be called in `onMount` only once. `disconnect()` in `onDestroy`.

═══════════════════════════════════════════════════════════════
CONTEXT — EXISTING REPO LAYOUT & ARCHITECTURE
═══════════════════════════════════════════════════════════════

- `frontend/src/lib/Assistant.svelte` (P4-T3): the floating panel component to render.
- `frontend/src/main.ts` must mount using Svelte 5 syntax: `mount(App, {target: document.getElementById('app')!})`.
- `frontend/index.html`: needs Inter font link and `background:transparent` on body.

═══════════════════════════════════════════════════════════════
DELIVERABLES
═══════════════════════════════════════════════════════════════

1. FILE: frontend/src/App.svelte (REPLACE scaffold placeholder)

   a. Script block:
      - Import `onMount`, `onDestroy` from 'svelte'.
      - Import `connect`, `disconnect`, `isConnected` from '$lib/ws'.
      - Import `Assistant` from '$lib/Assistant.svelte'.
      - `onMount(() => connect())` — establishes WebSocket connection.
      - `onDestroy(() => disconnect())` — cleans up on app teardown.

   b. Template:
      - Root `<div class="app-shell">` wrapping `<Assistant />`.
      - No other elements needed here — Assistant handles all visible UI.

   c. Style:
      ```css
      .app-shell {
        width: 100vw;
        height: 100vh;
        background: transparent;
        display: flex;
        align-items: flex-start;
        justify-content: flex-end;
        padding: 1rem;
      }
      ```
      This positions the Assistant panel in the top-right corner of the transparent window.

2. FILE: frontend/src/main.ts (MODIFY)
   Update to Svelte 5 mount syntax:
   ```typescript
   import { mount } from 'svelte'
   import App from './App.svelte'
   import './app.css'
   const app = mount(App, { target: document.getElementById('app')! })
   export default app
   ```

3. FILE: frontend/index.html (MODIFY)
   a. Set `<title>Local AI Assistant</title>`.
   b. Add Google Fonts Inter link in `<head>`.
   c. Add `<style>body { background: transparent; margin: 0; }</style>` in `<head>`.

4. Build and Test:
   a. Run `npm run tauri dev` — confirm the Assistant panel appears in the top-right of the screen.
   b. Confirm the rest of the screen is fully transparent (you can see through to the desktop).

═══════════════════════════════════════════════════════════════
IMPLEMENTATION HINTS
═══════════════════════════════════════════════════════════════
- In Svelte 5, `mount()` replaces the old `new App({target})` constructor. If the scaffold was generated with the old syntax, update `main.ts` accordingly.
- `onMount` runs after the component is mounted to the DOM — safe to call `connect()` here because the WebSocket store is initialized by import time, but `connect()` itself needs the DOM to be ready for any potential Tauri invocations later.
- If `document.getElementById('app')` returns null (wrong HTML template), check that `index.html` has `<div id="app"></div>` in the body.
