TASK: P50-T1 — Go Native System Audio Loopback

═══════════════════════════════════════════════════════════════
BACKGROUND & CONTEXT
═══════════════════════════════════════════════════════════════
In our old Python architecture (Phase 13), we implemented system audio loopback so the user could capture the interviewer's voice natively on Windows via WASAPI.
When we migrated to the Go/Wails backend in Phase 43, this feature was lost because the new Go STT engine only captures the default microphone!
We need to re-implement native driver-level loopback in Go to remain competitive with Sensei AI and Interview Coder.

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
1. AUDIO LOOPBACK IN GO
   - In `wails-app/backend/stt/`, upgrade the audio capture logic (using `github.com/gordonklaus/portaudio` or similar).
   - Implement support for capturing output devices (Windows WASAPI loopback).
   
2. DEVICE SELECTOR BINDINGS & EVENT EMISSION
   - Add Wails bound methods to `app.go`:
     - `GetAudioDevices() []AudioDevice`
     - `SetAudioDevice(id int, isLoopback bool) error`
   - **CRITICAL FIX FOR STUB:** When initializing `audioCapture` in `app.go`, DO NOT leave the callback as an empty stub!
   - You MUST actively route the `samples []float32` into `a.sttManager.TranscribeStream(samples)`.
   - `TranscribeStream` returns a `chan string`. You MUST start a background goroutine to range over this channel and emit the transcriptions to the frontend using `wailsruntime.EventsEmit(a.ctx, "on_transcript", transcript)`.
