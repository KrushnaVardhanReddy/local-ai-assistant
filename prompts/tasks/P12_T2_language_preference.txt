TASK: P12-T2 — Language Preference Setting (LLM Response Language Control)

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Allow the user to set their preferred programming language for LLM code responses
inside the Settings panel. This preference is then injected into every LLM system
prompt so the AI always returns code examples in the chosen language (e.g. Python,
JavaScript, Java, Go, C++).

Additionally, when a resume is uploaded (P11-T1), the backend's `/api/resume/extract`
endpoint should automatically detect the candidate's primary language from their skills
and return it as part of the extraction result, pre-filling the dropdown automatically.

═══════════════════════════════════════════════════════════════
BACKGROUND & MOTIVATION
═══════════════════════════════════════════════════════════════
Currently the LLM decides which language to use for code examples on its own, often
defaulting to whatever it thinks is most popular or matching the problem context.
During a coding interview, if the candidate is applying for a Python role and the
LLM returns a JavaScript answer, the candidate is forced to mentally re-translate it.

This feature gives the user explicit control: set once, effective for the entire
session. The preference is stored in localStorage (frontend), passed to the backend
on every system prompt assembly, and is auto-detected from the uploaded resume to
minimize friction.

BACKEND CHANGES: app.py
═══════════════════════════════════════════════════════════════

1. Add a new global variable at the top of app.py (alongside `candidate_context`):
   ```python
   preferred_language: str = ""  # e.g. "Python", "JavaScript", "Java"
   ```

2. Add a new Pydantic model:
   ```python
   class LanguagePreference(BaseModel):
       language: str  # The language name, e.g. "Python"
   ```

3. Add a new POST endpoint `/api/language`:
   - Accept `LanguagePreference`
   - Store the value in the global `preferred_language` variable
   - Return `{"status": "ok", "language": preferred_language}`

4. Add a GET endpoint `/api/language`:
   - Returns `{"language": preferred_language}`

5. Modify the existing LLM system prompt assembly to inject the language preference.
   Find the section where `system_content` is built (near the candidate_context
   injection added in P11-T1) and append:

   ```python
   system_content = config.SYSTEM_PROMPT
   if candidate_context:
       system_content += f"\n\nCandidate profile: {candidate_context}"
   if preferred_language:
       system_content += f"\n\nIMPORTANT: Always provide all code examples in {preferred_language}. Do not use any other programming language for code unless the user explicitly asks."
   if combined_context:
       system_content += f"\n\n{combined_context}"
   ```

   The language instruction must come AFTER the candidate profile but BEFORE the
   RAG context so the LLM treats it as a high-priority constraint.

BACKEND CHANGES: app.py — /api/resume/extract enhancement
═══════════════════════════════════════════════════════════════

Modify the existing `/api/resume/extract` endpoint (added in P11-T1) to also detect
the candidate's primary programming language from the resume text.

Change the LLM extraction prompt from:
```
system: "You are a resume parser. Extract the candidate's key technical skills,
         years of experience, notable projects, and target role from the resume text.
         Be concise. Output a single paragraph of max 150 words. No bullet points."
user: <the resume text>
```

To:
```
system: "You are a resume parser. Extract the candidate's key technical skills,
         years of experience, notable projects, and target role from the resume text.
         Be concise. Output a JSON object with exactly two keys:
           - 'summary': A single paragraph of max 150 words describing the candidate.
           - 'primary_language': The single most prominent programming language from
             the resume (e.g. 'Python', 'JavaScript', 'Java', 'Go', 'C++', 'TypeScript').
             If no clear language is found, return an empty string.
         Respond ONLY with valid JSON. No markdown, no extra text."
user: <the resume text>
```

Parse the JSON response from the LLM:
```python
import json

try:
    result = json.loads(llm_response_text)
    candidate_context = result.get("summary", llm_response_text)
    detected_language = result.get("primary_language", "")
    if detected_language and not preferred_language:
        # Only auto-fill if the user hasn't already set a manual preference
        preferred_language = detected_language
except (json.JSONDecodeError, KeyError):
    # Fallback: treat the whole response as the summary, no language detected
    candidate_context = llm_response_text
    detected_language = ""

return {
    "status": "success",
    "summary": candidate_context,
    "detected_language": detected_language
}
```

FRONTEND CHANGES: Settings.svelte

2. In `onMount`, load the current preference from the backend:
   ```typescript
   try {
     const resLang = await fetch(`${apiUrl}/api/language`);

       const data = await resLang.json();
       if (data.language) {

       }
     }

     console.error("Failed to load language preference", e);
   ```

IMPORTANT IMPLEMENTATION NOTES
═══════════════════════════════════════════════════════════════
- The `preferred_language` is IN MEMORY only on the backend (like `candidate_context`).
  It resets on backend restart. The frontend persists it in `localStorage` and reloads
  it into the backend on each `handleSaveSettings()` call.
- The LLM extraction prompt change (returning JSON instead of plain text) may not work
  with all LLM providers. Add robust JSON parsing with a try/except fallback to the
  original plain-text behavior (treat entire response as summary, no language detected).
- The `/api/language` GET/POST endpoints must be added before the WebSocket route in
  app.py to ensure correct FastAPI route ordering.
- Do NOT hardcode any language into the system prompt at startup. Language preference
  is `""` by default, meaning the LLM decides on its own. Only inject the constraint
  when `preferred_language` is non-empty.
- Keep all new UI styling consistent with the existing dark theme in Settings.svelte:
  background #222, border 1px solid #444, text white, labels #aaa.
- The hint text "Auto-filled from resume if detected" below the dropdown must be
  styled with font-size 0.72rem and color #666.
